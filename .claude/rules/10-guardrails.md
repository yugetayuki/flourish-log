# Aubade の設計制約（変更禁止）

このアプリは **「行動を起こさせる装置」ではなく「短時間の日次計測と週次フィードバックの装置」**。
行動変容の主役は環境設計（アプリの外）にあり、アプリは (a) 未定着行動の定着期の足場、
(b) 週次フィードバックループの計測層、の2役に限定する。

以下はオーナーと合意済みの行動科学的な設計判断。機能追加時も破らないこと。
抵触する変更を思いついたら、実装せずにオーナーへ確認する。

**判定は `guardrail-reviewer` サブエージェントに出す。** 自分で「たぶん大丈夫」と判断しない。
実装した本人が自分の変更を審査すると、書いた後の合理化が入る。別コンテキストで走らせる理由がそれ。
呼ぶ条件は下の7項目に触れうる変更すべてで、迷ったかどうかは基準にしない
（制約5に触れる変更は「自然な改善」に見えるので、そもそも迷いが発生しない）。

1. **連続日数（ストリーク）を表示しない。** 主指標は週次達成率（例 3/5）。
   根拠: 完璧主義傾向の強い利用者にとって、ストリークUIは断絶時の "what-the-hell effect" を誘発しやすい。
   Lally 2010（習慣自動化の中央値66日、1日の欠損は習慣形成に実質影響なし）もストリーク至上主義を支持しない。
2. **欠損は未入力であり、失敗として扱わない。** UI上も `miss`（中空ドット）と `ng`（未達）を区別する。
3. **朝の入力は1項目1〜2タップで完結させる**（ボタン・選択リスト・トグル）。
   1項目あたりの操作を増やす変更は不可。**項目数の上限は設けない。**
   - **「20秒以内」という上限は 2026-08-17 に撤廃した**（オーナー判断）。20秒は要件定義時の目安で、
     一度も実測されないまま「足せるか足せないか」の判定に使われ続けていた。
     撤廃時点で朝の動線は20行あり、**実測していれば既に超えていた可能性が高い**
     （guardrail-reviewer の指摘）。守れているか誰も知らない数字を判定基準に置くと、
     根拠のない拒否と、根拠のない承認の両方が起きる。
   - **撤廃したのは秒数であって、摩擦を増やさないという趣旨ではない。**
     判定は「1項目あたり何タップか」で行う。自由テキストは `weightVal` と `memo`（畳んだ状態）の
     2つが前例で、**朝の動線に出さない**なら追加を検討してよい。
   - 項目を足す前に見るのは秒数ではなく **`BACKLOG.md` の28日棚卸し**
     （「この項目を対象にした来週の一点を書けるか」）。書けない項目は足しても使われない。
   - 経緯（2026-08-16 / schema v9）: 元は「全項目ボタン式」だった。就寝・起床・YouTube を
     分の実値にした際、選択肢が17〜21になりボタンでは並べきれず select（iOS のネイティブピッカー）に
     変えた。**選択リストを許したのは物理量の入力だけ**で、主観尺度（眠れた感・気分）は
     引き続き段階ボタンのまま。
4. **相関ヒントは記録28日分未満ではロック。** 少データの相関はノイズであるため。閾値を下げない。
5. **ゲーミフィケーションは既定で追加しない。既定であって、全面禁止ではない**（反ドーパミン設計）。
   **2026-08-16 にオーナーが全面禁止を解除した**（それ以前の条文は「紙吹雪、バッジ、ランキング、
   連続ログインボーナス的なものは全面禁止」だった）。取り入れてよいのは、次の3つを**すべて**満たすものだけ:
   - (a) **その仕掛けで翌週の行動が具体的に変わる。** 「楽しくなる」「達成感がある」だけでは足りない。
     体感の改善しか説明できないものは装飾であって、機能ではない
   - (b) **断絶しても記録の習慣ごと崩れない。** 1日切れた・未達が続いたときに何が起きるかを書くこと。
     **ストリークは引き続き不可**（制約1は解除されていない。根拠が別で、こちらは生きている）
   - (c) **事実の提示にとどまり、行動の指示になっていない**（下の「恒久的にやらないこと」の線）
   **通知圧はこの解除に含まれない。** アプリ内の通知・催促・督促は引き続き追加しない
   （OS標準のリマインダー1本に委ねる運用は変えない）。
   解除の経緯: オーナーの言葉は「全面禁止は無しでよい、必要に応じて良いものは取り入れたい」。
   禁止そのものではなく、**検討せずに切り捨てること**をやめた、という趣旨。
6. **「眠れた感」は計測のみ。** 目標化・達成判定の対象にしない（主観状態は直接コントロール不能なため）。
7. 計測介入自体の効果根拠は Harkin et al. 2016（進捗モニタリングのメタ分析, d+ = 0.40）。
   効果は中程度であり、アプリを「主役」に拡張しない理由でもある。

## 恒久的にやらないこと

ストリーク表示 / ソーシャル比較 / 広告的演出 / ダークパターン。

**実績バッジは 2026-08-16 の解除でこの一覧から外した**（制約5 の (a)(b)(c) を満たせば検討可）。
ただし現時点で満たした案は無い。落とした理由は「解除されたから可」ではなく、
**(a) を通せなかった**（バッジがあっても翌週の行動が変わる説明を書けなかった）ため。

**残数カウント・督促表示も含む。** 例:「今週あと2回で目標達成」「バックアップしましょう」。
週次達成率の枠内に見えるため自然な改善として足したくなるが、実質は行動を促す装置であり、
上記の役割定義と制約5に抵触する。
**事実の提示は可、行動の指示は不可**、という線で引く。

前週の達成数の併記（v2.4）はこの線の内側と判断済み。比較そのものが週次フィードバックの目的であり、
週報テキストが既に前週データを Claude へ渡しているため。ただし増減の矢印・色は付けない（評価になるため）。
